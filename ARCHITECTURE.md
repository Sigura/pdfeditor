# PDF Toolkit — Architecture

## Module boundaries

```
packages/shared     zod schemas + inferred types: page model, edit operations, API DTOs.
                    No runtime deps besides zod. Imported by every other package.
packages/pdf-core   All PDF logic. Pure TypeScript on Node (uses node:crypto, node:fs for
                    font lookup). No HTTP, no React. Strict TS, no `any`.
  ranges.ts         page-range parser ("1-3,5,8-")
  merge.ts          mergePdfs(): page copy, outline merge, link remap, AcroForm rename;
                    arrangePdf(): reorder/rotate/remove pages in place (incremental)
  crypto/           standard security handler (RC4 / AES-128 / AES-256) for password input
  content/          content-stream tokenizer, parser (ops with byte offsets), serializer
  model/            interpreter (graphics + text state), text-run extraction, line/box
                    grouping, table detection → PageModel
  fonts/            PDF font loading: encodings, ToUnicode/CMap, widths, embedded program
                    parsing (TrueType/OpenType via fontkit, bare CFF, Type1), glyph coverage,
                    composition, system/local font lookup, fallback matching
  edit/             edit-state reducer (ops → final element state), text layout, op
                    generation per strategy, content-stream rewrite, table regeneration
  save/             incremental-update writer (append changed objects + xref + trailer)
apps/server         Hono HTTP API + `pdf-tool` CLI. Disk temp storage with TTL cleanup,
                    upload limits, filename sanitizing. Thin wrapper around pdf-core.
apps/web            React + Vite + Zustand + Tailwind. pdf.js canvas + HTML overlay.
fixtures/           Sample PDFs, generated by `fixtures/generate.ts` (reproducible).
```

Dependency direction: `web → shared`, `server → pdf-core → shared`. The web app never imports
pdf-core; everything that changes a PDF happens on the server.

## Page model

All coordinates are PDF user space of the page (points, y up, unrotated). The frontend maps them
with the pdf.js viewport, which handles `/Rotate` and CropBox offsets.

```ts
type Rect = { x0: number; y0: number; x1: number; y1: number };
type ContentRef = { streamId: string; opStart: number; opEnd: number }; // op indices, end exclusive
type TextRun = { id; pageIndex; text; bbox: Rect; fontRef; fontName; fontSize; color;
                 matrix /* text rendering matrix at run start */; charSpacing; wordSpacing;
                 contentStreamRef: ContentRef };
type TextBox = { id; runs: TextRun[]; bbox; lineHeight; align: 'left'|'center'|'right'|'justify' };
type Table   = { id; bbox; rows: Row[]; cols: Col[]; cells: Cell[]; borderStyle; confidence };
type Background = { bbox: Rect; color: Color | null }; // filled path (or image / unknown space: null), paint order
type PageModel = { pageIndex; width; height; rotate; textBoxes; tables; backgrounds; rulings; junctions; warnings; editable };
```

`streamId` is `page:<n>` (the page's `/Contents`, all parts concatenated as one logical stream)
or `xobj:<num>-<gen>` (a Form XObject). Every run maps to exactly one show operator
(`Tj`, `TJ`, `'`, `"`). IDs are deterministic (`p0-s0-op123`), so a re-parse of the original
document gives the same IDs, and edit lists stay valid across server restarts.

## Edit operations (`packages/shared/src/edits.ts`)

Discriminated union on `type`, validated with zod:

| type             | payload |
|------------------|---------|
| `replaceText`    | `elementId` (box or cell-less run box), `text` (lines split by `\n`), `overflow?: 'shrink'\|'wrap'\|'overflow'` |
| `addTextBox`     | `id` (client-generated), `pageIndex`, `bbox`, `text`, `fontSize`, `fontFamily?`, `color?`, `background?` |
| `deleteElement`  | `elementId` (box or table) |
| `moveElement`    | `elementId`, `dx`, `dy`, optional `width`/`height` (resize), `background?` (text boxes) |
| `tableInsertRow` | `tableId`, `index`, `position: 'above'\|'below'` |
| `tableDeleteRow` | `tableId`, `index` |
| `tableInsertCol` | `tableId`, `index`, `position: 'left'\|'right'`, `fit?: 'shrink'` (needed when the table would leave the page: the other columns shrink proportionally, the table keeps its width; otherwise rejected) |
| `tableDeleteCol` | `tableId`, `index` |
| `setCellText`    | `tableId`, `row`, `col`, `text`, `fontFamily?`, `fontSize?`, `color?`, `background?` (the cell fill, null = none); unset = column/template style, for scanned cells the ink colour and a size from the ink line height |
| `defineTable`    | `tableId`, `pageIndex`, `vertices` ((rows+1)×(cols+1) `{x,y,snapped}`, top row first), `spans`, `borderWidth`, `headerRows`, `origin`, `raster?` (scanned tables: `paper`, `ink?`, `fills?` [row][col], `inkBoxes?` [row][col] rect + `line` + `ascent`): the Table tool's confirmed setup. Redefines a detected table (same id) or defines a new one. Original-page coordinates, applied during analysis before all other ops |
| `resizeTable`    | `tableId`, `rowHeights?`, `colWidths?` (top-left corner fixed) |
| `setTextStyle`   | `elementId` (box), `color?`, `align?`, `lineSpacing?` (× font size), `background?`. Merged per box; layout keeps the box's font and in-line glyph offsets |
| `setPageFlow`    | `newPages: 'copy'\|'empty'`: how content continues past the last page (last one wins) |
| `arrangePages`   | `order` ([{`page`, `rotate?`}], edit indices in output order; left out = deleted), `blanks` ([{`width`, `height`}], appended to the edit document after the original pages, so they are editable). Last one wins. The flow follows `order`; pages it adds come after the blanks and are output last. Applied on download only (`arrangePdf`, so /Info, XMP and outlines stay); the preview and models keep edit indices and the editor maps display order to them |
| `deskewPage`     | `pageIndex`, `angle` (degrees, counter-clockwise, ±15), `paper`: straightens a tilted scan. Last one per page wins. Applied before analysis (`edit/deskew.ts`): the page content becomes one stream that fills the media box with `paper` and draws the old content rotated about the crop box centre, so the scan is placed rotated, never resampled. Every other op on the page is in straightened coordinates, which is what `/pdf?original=1` serves (`?original=raw` = the upload). The editor detects the angle on the upload (`rasterGrid.ts detectSkew`: projection profile of the ink over ±15°, 0.05° steps), offers "Straighten all" for tilts ≥ 0.3°, and only straightens pages without other edits; a straightened page's `scanLayout` is dropped and measured again |
| `scanLayout`     | `pageIndex`, `lines` (ink y ranges, original coordinates), `paper`: measured layout of a scanned page for the page flow |

The server keeps the original bytes plus the **full ordered list** of operations for a document.
`POST /edits` accepts `{ ops, mode: 'append' | 'replace' }`. Each call re-applies the full list to
the original. That makes undo/redo a client-side stack (send `replace` with the shorter list)
and keeps the result deterministic.

Pipeline: `ops → reduceEdits(model, ops) → EditState (final state per element) → render
(per stream: delete ops, insert ops) → incremental save`.

Reduced state (`edit/reduce.ts`): `boxes` (text, overflow, dx/dy, wrap width, style), `added` (new boxes),
`tables` (row/column boundaries, cell texts with the original cell they came from, dx/dy). Rows then
grow to fit their text (in `applyEdits`, which can lay text out), and `reflowBelow` shifts the boxes and
tables right below a table whose bottom edge changed; paths and images there get the same translation.

## Moves, new text, tables

- Move: the box goes through the normal layout path with its own text. Its content is inserted after
  the original text object as `q M cm … Q`, with `M = CTM × T(dx,dy) × CTM⁻¹`, so the shift is
  exact in user space whatever the CTM.
- New text (`addTextBox`, empty tables) is appended at the end of the page stream. The original page
  content is then wrapped in `q … Q`, so leftover CTM or clipping can't affect it.
- Table setup (`packages/shared/src/tableMesh.ts`, used by the editor and the tests): per-vertex mesh,
  snapping to `junctions` (ruling intersections), band check of each edge against `rulings`, merge/split,
  row/column split and join. The editor's Table tool (`TableSetup.tsx`) confirms it as `defineTable`.
- Table setup vertices move with their whole row and column line (`moveGridVertex`), so every cell
  stays a rectangle; the server uses the mean line positions.
- Tables (`model/tables.ts`): ruling lines are grouped by intersection (union-find), and positions
  are clustered into row and column boundaries. Detection proposes merges where an inner vertical
  border is not drawn (e.g. a "Total" row).
- Border pattern (`model/tablePattern.ts`, `TablePattern` in shared): per edge role (outerTop/Bottom/
  Left/Right, headerSeparator, bodyRow, innerVertical) the most common stroke set (offset, width,
  colour; double lines are several strokes), preferring pieces cut between snapped vertices; junction
  types seen; zebra fills of the body rows without merged cells (shortest repeating period).
- Regeneration (`patternContent` in `edit/apply.ts`) neutralizes the table's own path paint operators
  and draws from model + pattern at the end of the page: fills (zebra rows by their place among the
  repeating rows), then runs of drawn edges per grid line. Edges inside merged cells are skipped; a
  run reaches over a corner by the other edge's half-thickness and stops at a tee's centre line;
  inner lines are painted first, the header separator next, the outer border last. Only changed
  cells are re-emitted. Row inserts copy the nearest plain body row (height, merges, fills); merged
  cells grow, shrink and move with row/column inserts and deletes; header rows are tracked.
- Cell layout (`measureCell`/`planTable` in `edit/apply.ts`): per cell, the horizontal alignment comes
  from the cells of its column (header and body apart) when their text lines up, else from the padding;
  vertical alignment and text height from the laid-out original. Edited, inserted or narrowed cells wrap
  in the cell width minus the padding, never shrink, and their row grows (a merged cell grows its last
  row); other cells keep their alignment in the grown row. Inserted cells copy the nearest text cell of
  the column (body rows for body cells), else of the row.
- Images inside a cell (`cellImages`, `Cell.images`/`minSize`) move with it as `q cm … Do Q`, a pure
  translation at full precision, never scaled. `resizeTable` and column shrinking reject a cell smaller
  than its image plus up to 2 pt clearance; the editor stops border drags there.
- Scanned (raster) tables: the Table tool finds border lines in the rendered pixels when the page has
  no vector rulings under the rectangle (`editor/rasterGrid.ts` on a 4 px/pt render of the area,
  `background.ts renderRegion`: Otsu threshold, dark runs ≥ 30 pt and ≤ 4 pt thick, stacked runs joined
  (runs from 15 pt stack too, so words near 30 pt stay one thick stack), crossings → junctions), and on
  Confirm measures the paper, ink and per-cell background colours on the same kind of render (`raster` in the setup, `origin: 'raster'`). A changed raster table
  (`edit/raster.ts`) is redrawn at the end of the page from the scan itself, never resampled: paper over
  the old and new area; the scan under the table shifted by the change of its bottom edge; each kept cell
  as a crop of its interior at the original size, top-left aligned and clipped to the new cell; borders
  tiled along their length from the longest clean piece of an original edge of the same role (vertical
  pieces also by header/body side); junction squares cut from an original junction of the same type and
  line roles (snapped vertices first). Runs break at junctions and neighbouring pieces overlap by 0.5 pt,
  so antialiased clip edges leave no seams. Each piece is drawn from its own image XObject cut from the
  scan's samples (`edit/imageCrop.ts`: pixel-aligned, 8-px-aligned with a 4 px margin, same colour space,
  decode and mask, cached per source area), placed on the scan's own pixel grid; drawing the whole scan
  under each clip made pdf.js paint it ~140 times per page (seconds). Scans whose filter pdf-lib can't
  decode (DCT, JPX, CCITT, JBIG2) are decoded by pdf.js (the image alone in a one-page document, its
  operator list's image data: RGB or 1-bit grey after pdf.js's colour conversion, alpha as a soft mask),
  and their pieces are stored as Flate. On a JPEG page scan this renders a flowed page in ~0.5 s instead
  of ~8 s, costs ~0.2 s per edit and ~40 KB. Rotated scans are still drawn whole under the clip. A cell set with `setCellText` (even to empty) is painted with
  its background colour and gets new text (vector: a page font if it has the glyphs, else a substitute)
  in the ink colour, at the largest `inkFontSize` of the column (shared/tableMesh.ts: max of ascent ÷ 0.75
  and line ÷ 0.95, measured on real glyphs). At Confirm the editor also measures each cell's ink box inside
  the crop band (`raster.inkBoxes`: the tallest inked pixel-row run as `line`, its top to its baseline, the
  last row with ≥ 40 % of the busiest row's ink, as `ascent`); it becomes the cell `minSize` measured from
  the top-left corner (crops are anchored there), enforced like image cells until the cell is rewritten.
  After a structural edit the model's (and /PieceInfo's) ink boxes follow their cells into the new grid
  (rewritten and new cells have none), so the editor's size estimate (column, same side of the header)
  and a reopened file match the drawing.
  `tableInsertCol` with `fit: 'shrink'` keeps such columns at their minimum and narrows the others more.
- New text with no style box to copy, or with a font or size set by `setCellText`, is laid out first
  (`placeNew` in measure mode) and grows its row like other cells. A cell `background` repaints the fill;
  regenerated pattern fills are inserted where the table was painted (under the cell text), not at the
  page end.
- Page flow (`edit/paging.ts`, after all streams are written): content under a table moves with its
  bottom edge across the full page width. Each page's units (text boxes, table rows, paths, images; on
  scanned pages the ink rows of `scanLayout`) are split into header, footer and body. The header and footer
  are bands of clusters above/below the widest gap of at least 12 pt in the top/bottom 12% of the page,
  judged by pre-reflow positions, and tables are never bands. Body clusters (overlapping units; table rows
  are separate) that were pushed and end below the body bottom (footer top + 12 pt, else the document's
  bottom margin capped at 72 pt) continue at the top of the next page's body. That page's own body moves
  down by as much and overflows in turn. Cuts fall between clusters, so a row is never split. A page that
  takes part is redrawn from Form XObjects of the edited pages: one per drawn band (clipped and translated),
  each without the text and image draws outside its band. The text is dropped so the text layer has no
  duplicates, and the image draws so scans render fast. Footer bands moved by the reflow go back to their
  place. New pages only ever go after the last page, so existing page indices, ids and /PieceInfo never shift.
  Past the last page the response has `overflows` with `needsPage`, and the editor asks Copy header/footer /
  Empty page (same size) / Cancel. The choice is the op `setPageFlow`. A copy page draws the last page's
  header and footer bands (scan crops on paper for scanned pages). Scanned pages the flow reaches need a
  `scanLayout` (`needsLayout`). The editor measures it on the original PDF, straightened (`/pdf?original=1`, ink rows
  between the paper median and the 1st-percentile ink) and sends it with the same change. Page models
  after the flow show moved boxes and table rows on the pages that draw them, under their ids, and a table
  cut by the flow appears on both pages. `flowIn` marks continued areas, and `added` marks pages created by
  the flow. Both are closed to new text and the Table tool.
  A table cut by the flow (onto any page) is reported in `continuations` until a `tableContinuation`
  op answers it; past the last page a trial flow onto empty pages finds the cut, so the new-page prompt
  asks it too. With `repeatHeader`, every continued part starts with a band of the table's header rows
  drawn from its page, and its rows move down by that height; the continuation's model gets the header
  rows. Without it, the continued part starts with the table's top edge: a band around the top line of
  the source table (`tableTop`: the widest of the top/row strokes, or the scan border band), clipped to
  the table's width, drawn over the first row, whose own row line is clipped away. Header rows never end a
  page: when the row under them doesn't fit, they go to the next page with it (the table isn't cut there). A header/footer text box that reads like a page number ("Page 2", "2 of 5") is reported as the
  `pageNumber` of a `needsPage` overflow; `setPageFlow.pageNumbers: 'omit'` removes its runs from the
  copied bands. Scanned pages have no text, so the page-number question doesn't apply there.

## Background fill

`background` (colour, or null = none) paints `q rg x y w h re f Q` under the text, the laid-out bbox
plus 1 pt. The editor picks the colour where text lands (`apps/web/src/editor/background.ts`): the
topmost `backgrounds` entry under the box centre, else the most common rendered colour on a ring
around the box. Moves and new text get a fill only over non-white areas; in-place edits never get
one unless the user sets it. A moved box with a fill is drawn at the end of the page (with its
original CTM), so content painted later than the original text can't hide it.

## Text removal

A removed show operator is replaced by an operator with **the same text-space advance and no
glyphs**: `(Hello) Tj` → `[-2222.5] TJ`, `'` → `T* [-…] TJ`, `"` → `aw Tw ac Tc [-…] TJ`.
Following text on the same line keeps its position, and the old glyphs are gone from the file
(not covered). New text is inserted right after the `ET` of the text object that held the
first run, wrapped in `q … Q` so CTM and clipping match the original.

The white-rectangle fallback is used only when a stream can't be parsed. It is reported as a
`coverOnly` warning, both in the API response and in the UI.

## Font-strategy decision flow

```
edited box text
 │
 ├─ font is Type3 → all codes present in CharProcs/encoding? → S1 else S3(fallback only)
 │
 ├─ S1 "original": every char maps to a code (inverse ToUnicode, else encoding/glyph names),
 │       the code has a glyph in the embedded program (or the font is a non-embedded
 │       standard-14 and the code is in its encoding) and has a width
 │       → rewrite show operators with the same font resource, size, Tc/Tw/Tz, color
 │
 ├─ S2 "substitute": base name (subset prefix stripped, e.g. ABCDEF+Arial-BoldMT) matched
 │       against fonts/ dir + system font dirs (PostScript name, then family+style, then
 │       metric-compatible aliases: Helvetica/Arial→Liberation Sans, Times→Liberation Serif…)
 │       and the font covers every char → embed subset (Type0/Identity-H + ToUnicode)
 │
 └─ S3 "emulated", decided per glyph:
         a) glyph outline from the embedded program            → vector path
         b) NFD composition from glyphs in the embedded program → base + positioned accent
            (é=e+´, ş=s+¸, İ=I+˙; dotless i/j used as bases when present)
         c) closest fallback font (serif/sans, weight, italic from FontDescriptor + name),
            scaled to the original cap height / x-height / advance, emboldened with a
            stroke when the original stem is heavier                → vector path
         d) none → error NO_GLYPH_SOURCE (no faked output)
       + invisible text layer (3 Tr) in an embedded Unicode font, horizontally scaled to the
         emulated advances, so the result stays searchable and copyable
```

Implementation notes: `fonts/program.ts` gives one glyph API over TrueType/OpenType (fontkit), bare
CFF (`fonts/cff.ts` reads the top DICT, charset and built-in encoding, then wraps the data in a
minimal `OTTO` sfnt so fontkit interprets the charstrings) and Type1 (`fonts/type1.ts`: eexec,
charstring interpreter with flex, hint replacement and seac). Bare CFF advances are approximated
from the glyph bbox, since the wrapper has no hmtx. `fonts/lookup.ts` indexes fonts, and
`edit/emulate.ts` resolves S3 glyphs. In S3, characters the original font has a code for stay real
text. Outline glyphs are drawn after the text object (`q cm path f Q`), and their 3 Tr copy goes
inline in the text object, so reading order is kept. Standard-14 fonts have no outlines, so their
composed glyphs are shown as positioned original glyphs inside `/Span <</ActualText …>> BDC`.
pdf-lib's random subset suffix is replaced by a hash-derived `ABCDEF+` tag, so output stays deterministic.

S1/S2/S3 is chosen per box: S1 only when all glyphs are covered, because mixing the subset with a
re-embedded copy of the same face gains nothing. The per-glyph decision happens inside S3. The
edit response reports `{ elementId, strategy, glyphs: { original, composed, fallback } }`.
The UI shows it as a badge.

Rasterizing at ≥300 DPI is listed in the spec as a last resort. Every case where it could apply
has no glyph source to rasterize from, so the server reports `NO_GLYPH_SOURCE` instead.

## Saving

pdf-lib loads the original. On save, every object is re-serialized and compared with its
serialization at load time. Only changed objects, plus new ones (embedded fonts, new content
streams), are appended as an incremental update (`xref` section + trailer with `/Prev`).
Untouched bytes stay byte-identical.

Confirmed table models (setup with the current vertices and spans, plus the pattern) are written to
the page's `/PieceInfo /PDFToolkit /Private` as a JSON stream (`model/pieceInfo.ts`), with the
`/LastModified` dates the spec requires there (page and data dictionary; `/Info` and XMP are not
touched). On open they apply to the detected table they overlap most and their pattern is used as
is; a `defineTable` op for that table wins over the stored model. Encrypted inputs that were opened with a password get a
full (decrypted) rewrite instead.

## Security

- Upload limit (default 50 MB per file, 20 files), MIME and `%PDF-` magic check.
- File names are only used, sanitized, for `Content-Disposition`. Storage uses random IDs.
- pdf.js runs with `isEvalSupported: false`, `enableScripting: false`. Embedded JavaScript
  (`/JS`, `/OpenAction`) is never executed.
- Temp directory is cleaned on a TTL (default 1 h) and on startup.

## Known limitations (detected, reported, not faked)

- Scanned pages: no text runs. The model has `editable: false` and the reason.
- Type3 fonts: only S1 (existing CharProcs) or S3c fallback.
- Fonts with broken/missing ToUnicode and non-standard encodings: text decodes as `�`.
  Such runs are marked `decodable: false` and can't be edited, only deleted or moved.
- Vertical writing (Identity-V) is extracted but not editable.
- Text in Form XObjects shared by several pages: editing changes it everywhere. Reported as a
  warning.
- Table regeneration assumes axis-aligned grids. Rotated tables are only detected.
